# AGENTS.md

## Cursor Cloud specific instructions

This repository is the **Pixelocity / WebGPU Shader Effects** app (Create React App + React 19 + WGSL compute shaders, with an optional C++/WASM renderer). See `README.md` and the `scripts` in `package.json` for the canonical commands. Notes below are the non-obvious things that bite you in the headless Cloud VM.

**Shader upgrades:** live contract is [`docs/SHADER_UPGRADE_BATCH.md`](docs/SHADER_UPGRADE_BATCH.md). Add 2–4 named visual ideas to the existing effect. Do not reimagine the shader. Do not treat bindings / ACES / `updatedParams` / springs as the upgrade. Plumbing reference: [`docs/agents/CLOUD_UPGRADE.md`](docs/agents/CLOUD_UPGRADE.md). Bindings: [`docs/agents/WGSL_BUILTINS_GENERATIVE.md`](docs/agents/WGSL_BUILTINS_GENERATIVE.md). Shaders get the 13 bindings from `#include "_prelude.wgsl"` — never paste them (CI fails); migrate a pasted header with `python3 scripts/migrate_to_prelude.py --files public/shaders/<id>.wgsl`, which is header-only and never bumps `Upgraded:`.

### Services / commands
- **Dev server:** `npm start` (CRA on port 3000). The `prestart` step regenerates `public/shader-lists/*.json` and the unified manifest with **relative** same-origin shader paths (no `--base-url`; set `SHADER_LIST_BASE_URL` only for deploy builds). Use `BROWSER=none` to avoid CRA trying to open a browser.
- **Unit tests:** `npm test -- --watchAll=false --ci` (Jest via craco; ~159 suites / ~1330 tests, all pass). Do **not** call `npx react-scripts test` directly: it skips the craco `moduleNameMapper` and 11 WASM-bridge suites fail on `./bridge/api.js`.
- **Lint:** `npm run lint` (`eslint src --ext .ts,.tsx`). Lint is **gating** in CI (the `lint` job runs `npm run lint` with no `|| true`): errors fail, while the ~370 pre-existing warnings are tolerated. Keep it at 0 errors.
- **Typecheck:** `npm run typecheck` (`tsc --noEmit`) and `npm run typecheck:scripts`. `tsconfig.json` has `strict` + `noUncheckedIndexedAccess`, so indexed reads are `T | undefined` — guard them rather than using `!`.
- **CI verify gates:** `npm run verify:toolchain-foundation` chains the bundle-size, dependency-boundary, generated-sync, catalog-count, WASM-bridge-sync, `_prelude` migration, naga-wasm and thumbs-deferral checks; run it (after a build) before pushing changes that touch those areas.
- **Build:** `npm run build` runs `wasm:build` once in `prebuild`, then CRA; CI `wasm` job compiles separately. Use `SKIP_WASM_BUILD=1 npm run build` without emcc. `npm run wasm:compdb` (needs emsdk sourced) writes the gitignored `wasm_renderer/compile_commands.json` for clangd.

### Hard environment limitations in the Cloud VM (these are NOT bugs you introduced)
- **No hardware GPU adapter.** The headless VM has no Vulkan ICD, so a default browser's boot probe fails (`navigator.gpu.requestAdapter()` returns null) and the app shows the **WebGPU required** overlay with `window.webgpuProbe` attempt JSON — not a silent Canvas2D fallback. **Software WebGPU does work:** Playwright's bundled Chromium launched with `--enable-unsafe-webgpu --enable-features=Vulkan --use-vulkan=swiftshader --use-webgpu-adapter=swiftshader --enable-unsafe-swiftshader --use-angle=swiftshader` gets a SwiftShader adapter (timestamp-query, subgroups, worker OffscreenCanvas). All six flags matter — without `--use-angle=swiftshader` canvas presentation drops the Dawn instance and later `popErrorScope` / `mapAsync` reject. Compositor screenshots of the WebGPU canvas stay blank, so read pixels back through the renderer (`__pixelocity__.captureThumbnailPng`). `npm run test:engine2` runs the `swiftshader` Playwright project against `build/` (and `npm run test:engine2:smoke` the renderer smoke specs in both render threads). The TS renderer runs in a **render worker by default** (`docs/RENDER_WORKER.md`); use `?renderer=main` to keep it on the page. It is slow (~2 fps at the default working size) and not a performance reference.
- **gpu-chores (Tier 4b)** adopt the renderer’s `GPUDevice` only when `window.webgpuProbe.ok === true`. On this VM chores stay idle (no silent CPU pre-FX). Kill switch: `?no_gpu_compute` (only when probe succeeded). Domain FX remain Tier 4a (`public/shaders/`). See `docs/GPU_CHORES.md`.
- **External media hosts are network-blocked.** Image/video manifests and assets come from `storage.noahcohn.com`, `storage.googleapis.com`, and Unsplash; outbound requests to these are reset/blocked from the VM, so "Random Image" and remote shader/media loads won't display content. Local files under `public/` (e.g. `public/thumbnails/*.png`) are same-origin and reachable.
- **Emscripten (`emcc`) may not be installed.** `wasm:build` **fails** if `emcc` is missing unless you set `SKIP_WASM_BUILD=1` to use committed artifacts in `public/wasm/`. Use `SKIP_WASM_BUILD=1 npm run build` in this VM. CI builds WASM in the dedicated `wasm` job. Playwright smoke tests in `tests/` need a production build + WASM + a real GPU.
- **`sharp` postinstall** downloads a libvips binary from GitHub during `npm install`; this can transiently fail with `ECONNRESET`. Re-running `npm install` resolves it.
