## Hard rules for forks
1. Edit ONLY your own `public/shaders/<id>.wgsl` and `shader_definitions/**/<id>.json`. No git commit / checkout / stash / reset / add. No edits to `reports/*`, `public/shader-lists/*`, `src/contracts/*`, search index, ledger — the coordinator does those. **Do not run `git checkout` at all** (forks have run `git checkout -- reports` before despite the rule).
2. Saved `params` (ids, names, defaults, min/max/step, mapping) stay byte-exact. All four sliders must stay live and keep their role; a default slider position must still produce the HEAD *magnitude* of the thing it controls unless the card says it was dead.
3. Bindings come from the include; never paste them. Keep `@workgroup_size(16,16,1)`.
4. Idea comments: `// ── Idea n: <name> (<§12.2 row or "native">) ──` at the place it acts. Header gets `//  Upgraded: 2026-11-10` (append to an existing Upgraded line as `2026-10-05, 2026-11-10`), `//  Ideas: …` (names + §12.2 rows; **append** to an existing Ideas line, never delete earlier ideas), `//  A packing: …` (truthful). Keep the existing banner text; add lines, do not delete the identity description. No `fast-motion` in Features.
5. JSON: add tags only if true (`audio-reactive` only if `plasmaBuffer[0].xyz` visibly modulates something; `mouse-driven` only if the pointer changes the picture; `upgraded-rgba` only if ACES is in the WGSL and the card is implemented). **Do not lengthen `description` by more than ~80 chars** (long descriptions dilute the CLIP search index and fail a Vitest). No new schema keys. `x-meta.upgrade.params` may be added/aligned additively if the file has none.
6. Audio is `plasmaBuffer[0].xyz` ONLY. `plasmaBuffer[1..]` is out of range (the buffer is a single vec4) and `extraBuffer[133..255]` is re-uploaded as ZERO every frame (`src/renderer/webgpu/audioDepth.ts` writes the whole 256-float scratch, so **any extraBuffer spring/state never persists**). `zoom_config.w` is mouse-down, NOT audio; `u.config.y` is the ripple COUNT, never "dt" and never "a click is alive" (ripples are not aged out — scan `ripples[i]` with `age = time - r.z` in a window).
7. State that must persist between frames: the **A-texel scheme** (exemplar `public/shaders/cyber-lens.wgsl` ~L160-280: A texel (0,0) = state, texel (1,0) = `(…, 0.7371)` sentinel with tol 1e-4/1e-3, zero the history read on those two texels, store `fract(time)` and `dt = clamp(fract(time - last), 0.001, 0.05)`; A may be rgba16float on balanced/battery tiers). Use it only where the card says so. Do not invent new state elsewhere. Per-pixel history in C/A that the file already owns is fine.
8. Exact `textureLoad(dataTextureC, …)` for history — no filtering sampler on C. Where HEAD bilinear-samples C, hand-roll the bilerp from four exact loads (clamped coords). **Use the texel centre: `(pixel + 0.5)/res` ⇒ `pos = pixel + 0.5`; a bilerp at `pixel/res` reads half a texel off** (batch-30 found a +0.11 uv drift in 60 frames from that).
9. ACES only on display RGB and only where the card says; **clamp ≥ 0 before `aces()`** (the catalog fit maps negatives to bright). If A is fed back through C as colour, store the pre-ACES state and tone-map only on `writeTexture`, or decode — never ACES→C→ACES. Alpha must stay semantic (never a bare `1.0`).
10. Naga-clean: no reserved identifiers (`target`, `array`, `filter`, `sample`, `ref`, …), no swizzle assignment (`v.rgb = …`), no `pow` with a possibly-negative base (use `x*x` / `exp`), no `fwidth`/`dpdx`, guard `normalize()` / divisions. Branchless masks (`select`, `mix`) preferred. No `unpack2x16float(pack2x16float(x))` (passes precommit, fails CI's naga-wasm).
11. **Visibility is measured, not assumed.** Batch-30's unanchored reviewers found 5 of 10 first-round ideas invisible (≈2°, 0 % of pixels > 0.02, mean |Δ| 0.001, Δ=0 at default sliders). For every idea, render the file with that idea's contribution multiplied to zero (a scratch copy with a `const IDEA_n: f32 = 0.0` switch, or edit the scratch copy) and report **% of pixels whose max-channel |Δ| > 0.02** and mean |Δ|, at 192 AND 576, at DEFAULT sliders. Target: several percent of the frame (or of the pointer/ripple region for pointer-local ideas, say which). If an idea is below that, strengthen it (within the card's identity) or replace it per rule 15.
