## Hard rules for forks
1. Edit ONLY your own `public/shaders/<id>.wgsl` and `shader_definitions/**/<id>.json`. No git commit / checkout / stash / reset / add. No edits to `reports/*`, `public/shader-lists/*`, `src/contracts/*`, search index, ledger — the coordinator does those. **Do not run `git checkout` at all** (forks have run `git checkout -- reports` before despite the rule).
2. Saved `params` (ids, names, defaults, min/max/step, mapping) stay byte-exact. All four sliders must stay live and keep their role; a default slider position must still produce the HEAD *magnitude* of the thing it controls unless the card says it was dead. (aurora-mantis params are RAW ranges, not 0–1.)
3. Bindings come from the include; never paste them. Keep `@workgroup_size(16,16,1)`.
4. Idea comments: `// ── Idea n: <name> (<§12.2 row or "native">) ──` at the place it acts; rescues `// ── Rescue n: … ──`. Header gets `//  Upgraded: 2026-11-15` (append to an existing Upgraded line as `2026-10-10, 2026-11-15`; a file with no Upgraded line gets `//  Upgraded: 2026-11-15`), `//  Ideas: …` (names + §12.2 rows; **append** to an existing Ideas line, never delete earlier ideas), `//  A packing: …` (truthful). Keep the existing banner text; add lines, do not delete the identity description. No `fast-motion` in Features.
5. JSON: add tags only if true (`audio-reactive` only if `plasmaBuffer[0].xyz` visibly modulates something; `mouse-driven` only if the pointer changes the picture; `upgraded-rgba` only if ACES is in the WGSL and the card is implemented). **Do not lengthen `description` by more than ~80 chars** (long descriptions dilute the CLIP search index and fail a Vitest). No new schema keys. `x-meta.upgrade.params` may be added/aligned additively if the file has none. (gen-ethereal-… has no `features` array today; you may add one with only true tags.)
6. Audio is `plasmaBuffer[0].xyz` ONLY. `plasmaBuffer[1..]` is out of range (the buffer is a single vec4) and `extraBuffer[133..255]` is re-uploaded as ZERO every frame (`src/renderer/webgpu/audioDepth.ts` writes the whole 256-float scratch, so **any extraBuffer spring/state never persists**). `zoom_config.w` is mouse-down, NOT audio; `u.config.y` is the ripple COUNT, never "dt" and never "a click is alive" (ripples are not aged out — scan `ripples[i]` with `age = time - r.z` in a window). `textureLoad(dataTextureC, …)` is NOT an audio source.
7. State that must persist between frames: the **A-texel scheme** (exemplar `public/shaders/cyber-lens.wgsl` ~L160-280). Use it only where the card says so (kaleido already has one — keep it byte-for-byte in behaviour). Do not invent new state elsewhere. Per-pixel history in C/A that the file already owns is fine.
8. Exact `textureLoad(dataTextureC, …)` for history — no filtering sampler on C. **Use the texel centre: `(pixel + 0.5)/res`** (a bilerp at `pixel/res` reads half a texel off — batch-30 found a +0.11 uv drift in 60 frames).
9. ACES only on display RGB and only where the card says; **clamp ≥ 0 before `aces()`** (the catalog fit maps negatives to bright; ACES(−0.18)≈0.68). If A is fed back through C as colour, keep HEAD's documented packing; never newly introduce ACES→C→ACES. Alpha must stay semantic (never a bare `1.0` on a display store).
10. Naga-clean: no reserved identifiers (`target`, `array`, `filter`, `sample`, `ref`, …), no swizzle assignment (`v.rgb = …`), no `pow` with a possibly-negative base (use `x*x` / `exp`), no `fwidth`/`dpdx`, guard `normalize()` / divisions / `atan2(0,0)`. Branchless masks (`select`, `mix`) preferred. No `unpack2x16float(pack2x16float(x))` (passes precommit, fails CI's naga-wasm).
11. **Visibility is measured, not assumed.** Batch-30's unanchored reviewers found 5 of 10 first-round ideas invisible (≈2°, 0 % of pixels > 0.02, mean |Δ| 0.001, Δ=0 at default sliders). For every idea, render the file with that idea's contribution multiplied to zero (a scratch copy with a `const IDEA_n: f32 = 0.0` switch) and report **% of pixels whose max-channel |Δ| > 0.02** and mean |Δ|, at 192 AND 576, at DEFAULT sliders. Target: several percent of the frame (or of the pointer/click region for pointer-local ideas — say which). If an idea is below that, strengthen it (within the card's identity) or replace it per rule 15.
