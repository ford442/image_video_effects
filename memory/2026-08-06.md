## WASM C++ mode Windows adapter failure

- Symptom: TS WebGPU OK; switch to C++ → all 4 emdawn requestAdapter fail
  ("Instance reference no longer exists" / "No available adapters").
- Cause: `switchRenderer` kept TS device alive until WASM succeeded → dual exclusive
  WebGPU ownership on same canvas (Windows Chrome rejects second adapter).
- Fix: release exclusive webgpu/wasm before the other inits; restore previous on fail.
  Tests in RendererManager.test.ts. device.cpp comment only (no binary rebuild needed).

## WASM adapter root cause #2 — TimedWaitAny

- Dual-device release was necessary but not sufficient.
- Real bug: `wgpuCreateInstance` without `WGPUInstanceFeatureName_TimedWaitAny`,
  while adapter/device paths call `wgpuInstanceWaitAny(..., UINT64_MAX)`.
  emdawn returns WaitStatus_Error immediately → callbacks never run → fake
  "adapter failed" then late "Instance reference no longer exists" after Shutdown.
- Fix: enable TimedWaitAny + limits on instance; log WaitAny status; rebuild
  with emcc 6.0.3. Also Canvas2D recovery after WebGPU (replace canvas element).

## setInterval Violation / render hitch

- Chrome `[Violation] setInterval handler took 200–350ms` from adaptive quality:
  once/sec scale changes rebuilt full internal WebGPU textures.
- Fix: 4s cooldown + 2-sample streak before scale change; HUD/FPS setState only
  when values actually change. Tests in adaptivePerformance.test.ts.
