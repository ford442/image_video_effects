## getGPUTimings JS/C++ ABI (WASM bridge)

- Playwright `WASM getGPUTimings API surface` failed because `__pixelocity__.getGPUTimings()` returned `{}`.
- Cause: `src/wasm/bridge/uniforms.js` called `ccall('getGPUTimings', 'string', [], [])` and JSON-parsed. C++ is `void getGPUTimings(float*, float*, float*, int*)`. Empty/void return → `{}`. Catch also swallowed ABI errors into `{}`.
- **Do not change C++ to return JSON.** Keep the out-param ABI. JS must `_malloc(16)`, `ccall` with four pointers, `getValue` float/float/float/i32, `_free`. Synthesize `timingSource` (`gpu-timestamp` if available, else `wall-clock`; `unavailable` when not initialized). Always return the `GPUTimings` shape — never `{}`.
- **Edit `src/wasm/bridge/*.js`, not `wasm_renderer/bridge/*.js`.** `concat_bridge.sh` copies **from src/wasm/bridge to** `wasm_renderer/bridge` and `public/wasm/bridge`. Webpack imports `src/wasm/wasm_bridge.js`. Editing `wasm_renderer/bridge` is overwritten on the next `wasm:build`. JS-only changes do **not** need `emcc`; `SKIP_WASM_BUILD=1 npm run wasm:build` still runs concat. Playwright needs a CRA rebuild to pick up the webpack bundle.
- Docs/comments in `build.sh` previously said the opposite (edit wasm_renderer). Comments in `concat_bridge.sh` + `build.sh` now match the real copy direction.
- Jest: `WASMBridge.uniforms.test.ts` covers pre-init zeros, pointer ccall, and gpu-timestamp mapping. 6/6 pass.
