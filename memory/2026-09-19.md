## Copilot track expansion → filed #1294 (mechanism overturned)

Expanded the #1264 TS slice with Gemini Pro / Kimi K2 / Grok, then checked every claim against the tree.

**Decision: contract-driven generation in place, NOT a runtime `#include` expander.**
Six consumers read raw `.wgsl` text; two fail silently:
1. `src/renderer/bindGroupValidator.ts:62` — requires bindings 0–12 textually present; `compileShader`
   substitutes `FALLBACK_WGSL` (red tint) on failure. **Hard break** under runtime include.
2. `src/renderer/webgpu/pipeline.ts:104` `analyzeShaderBindings` — regex-scans `@binding(7|8|9|13)` to
   decide whether to skip feedback/history copies. **Silent visual break, zero test coverage.**
3. `pipelineCacheKey(wgsl, colorFormat)` hashes raw source. 4. `parseWorkgroupSize` regex-scans.
5. `scripts/wgsl_precommit_gate.py:99` `run_naga(wgsl_path)` takes a **file path** → naga chokes on `#include`.
6. `build-shader-search-index.mjs`, catalog/binding audits, `ShaderScanner.tsx:237`, `shaderApi.ts:513`.

Generation in place breaks none of them — the file on disk stays complete WGSL. `verify:uniforms`
already enforces `uniforms_layout.json` against TS + C++ + docs but **not the 1,365 catalog files**;
that asymmetry is the real defect. Extend that gate rather than adding a sibling.

**If the include route is ever revived:** the seam is `src/utils/fetchShaderWgsl.ts:43` (the single TS
load point, from `pipeline.ts:117`), NOT `ShaderCompilation.ts`. Route `src/wasm/bridge/shader.ts:76`
`loadShaderFromURL` + `:93` `reloadShaderFromURL` through it and both backends share one JS expander —
C++ `LoadShader(const char* id, const char* wgslCode)` (`pipeline.cpp:538` ← `main.cpp:41`) already
receives WGSL as a string, so there is no marshaling cost and no C++ parser needed.
