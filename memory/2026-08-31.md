## WASM adapter gate: maxTextureDimension2D need=79984

- Symptom: `pixelocity_wasm.js` printed `maxTextureDimension2D have=16384 need=79984 INSUFFICIENT` and refused Pascal/Chrome GPUs that report 16384.
- Root cause 1: JS `ccall('initWasmRenderer', …, ['string','number','number'], [selector,w,h])` vs C++ `(int width, int height, const char* selector)` — selector heap pointer became width (~79984) and CheckLimit treated that as need.
- Root cause 2: C++/TS gated `maxTextureDimension2D` on canvas `max(w,h)` instead of a named 2D texture floor.
- Fix: ccall order `(w,h,selector)`; contract/TS/C++ need + `requiredLimits` = **8192** from `webgpu_limits.json` (not maxBufferSize / pixel count / width×height / pointer). Rebuilt `public/wasm/pixelocity_wasm.{js,wasm}`. Until redeploy: `?renderer=webgpu` (#1200).
- Gates: `verify:device-policy` OK; focused Jest webgpuDevicePolicy 9/9. Real-GPU Pascal confirm external.
