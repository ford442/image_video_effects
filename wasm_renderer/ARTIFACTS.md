# WASM Artifacts — Locations & Strategy

## Artifact strategy (Phase 2)

We use **CI-built, committed baseline**:

| Artifact | Location | Role |
|----------|----------|------|
| C++ sources | `wasm_renderer/*.cpp`, `*.h` | Source of truth for renderer logic |
| JS bridge (TypeScript) | `src/wasm/bridge/*.ts`, `src/wasm/wasm_bridge.ts` | **Hand-edited SoT — edit here only** |
| Bridge types | `src/wasm/wasm_bridge.d.ts` | Public contract for generated ESM |
| Emscripten output | `public/wasm/pixelocity_wasm.{js,wasm}` | Runtime-loaded WASM module |
| Bridge copies | `wasm_renderer/wasm_bridge.js`, `public/wasm/wasm_bridge.js`, `*/bridge/*.js` | Generated by `concat_bridge.sh` — do not edit |

**Why committed binaries?** So `npm start` works on machines without Emscripten. CI always rebuilds from C++ and fails if sources change without a matching build.

**Not using Git LFS** — artifacts are ~200 KB total; CI rebuild + validation is sufficient drift protection.

## Canonical vs generated paths

```
src/wasm/bridge/*.ts + src/wasm/wasm_bridge.ts   ← EDIT HERE
        │
        ├─ webpack compiles ──► app bundle (WASMRenderer.ts)
        └─ concat_bridge.sh / esbuild
                ├─ wasm_renderer/bridge/*.js + wasm_bridge.js
                └─ public/wasm/bridge/*.js + wasm_bridge.js   (useWASM dynamic import)

wasm_renderer/main.cpp + renderer.cpp
        │
        └─ emcc ──► public/wasm/pixelocity_wasm.{js,wasm}
```

`npm run verify:wasm-bridge-sync` fails if the generated trees drift from TypeScript emit.

## Build commands

```bash
npm run wasm:build      # Requires emsdk; fails if emcc missing
npm run wasm:validate   # Checks sizes, magic, exports, generated-copy equality
npm run verify:wasm-bridge-sync  # TypeScript SoT vs generated JS
npm run wasm:clean      # Remove build/ and public/wasm/
```

### Skipping WASM build intentionally
`SKIP_WASM_BUILD=1` still runs bridge concat, then skips emcc.

Headless dev VMs without Emscripten can use committed artifacts:

```bash
SKIP_WASM_BUILD=1 npm run build
```

CI jobs that consume pre-built artifacts from the `wasm` job set this automatically.

## CI pipeline

1. **`wasm` job** — installs emsdk (`mymindstorm/setup-emsdk@v14`), runs `wasm:build`, `wasm:validate`, `verify:wasm-bridge-sync`, WASM Jest smoke tests, freshness check, uploads artifacts.
2. **`test` job** — downloads WASM artifacts, runs full unit tests + CRA build with `SKIP_WASM_BUILD=1`, re-validates artifacts (`verify:toolchain-foundation` includes bridge sync).
3. **`test-wasm-e2e` job** — downloads artifacts, production build, Playwright smoke tests (`tests/wasm-renderer.smoke.spec.ts`).

See [`WASM_BUILD_CI_GUIDE.md`](../WASM_BUILD_CI_GUIDE.md) for troubleshooting.
