# WASM Artifacts — Locations & Strategy

## Artifact strategy (Phase 2)

We use **CI-built, committed baseline**:

| Artifact | Location | Role |
|----------|----------|------|
| C++ sources | `wasm_renderer/*.cpp`, `*.h` | Source of truth for renderer logic |
| JS bridge (TypeScript) | `src/wasm/bridge/*.ts`, `src/wasm/wasm_bridge.ts` | **Hand-edited SoT — edit here only. Never edit `public/wasm/bridge/*.js`.** |
| Bridge types | `src/wasm/wasm_bridge.d.ts` | Public contract for generated ESM |
| Emscripten output | `public/wasm/pixelocity_wasm.{js,wasm}` | Runtime-loaded WASM module |
| Bridge copies | `wasm_renderer/wasm_bridge.js`, `public/wasm/wasm_bridge.js`, `*/bridge/*.js` | Generated by `concat_bridge.sh` — do not edit |
| WGSL validator | `tools/naga_wasm/` → `public/wasm/naga_wasm.wasm` | GPU-less naga, built by `npm run naga-wasm:build`. Unrelated to the renderer module. |
| Validator loader | `public/wasm/naga_wasm.js` | **Hand-written**, not emitted by `emit-wasm-bridge.mjs`. Shared by Node and the browser. |
| ESM marker | `public/wasm/package.json` | `{"type":"module"}`. Everything in `public/wasm/` is already ESM; this only tells **Node** so, silencing `MODULE_TYPELESS_PACKAGE_JSON` when `verify-naga-wasm.mjs` imports the loader. Browsers ignore it. |

**Why committed binaries?** So `npm start` works on machines without Emscripten. CI always rebuilds from C++ and fails if sources change without a matching build.

**Not using Git LFS** — artifacts are ~200 KB total; CI rebuild + validation is sufficient drift protection.

## Canonical vs generated paths

```
src/wasm/bridge/*.ts + src/wasm/wasm_bridge.ts   ← EDIT HERE
        │
        ├─ webpack compiles ──► app bundle (WASMRenderer.ts)
        └─ concat_bridge.sh / esbuild
                ├─ wasm_renderer/bridge/*.js + wasm_bridge.js
                └─ public/wasm/bridge/*.js + wasm_bridge.js   (useWASM dynamic import)

wasm_renderer/main.cpp + renderer.cpp
        │
        └─ emcc ──► public/wasm/pixelocity_wasm.{js,wasm}

tools/naga_wasm/src/lib.rs                       ← separate crate, separate artifact
        │
        └─ cargo (wasm32) ──► public/wasm/naga_wasm.wasm
                                    ├─ node   scripts/verify-naga-wasm.mjs
                                    └─ browser src/utils/nagaWasm.ts (dynamic, out of bundle)
```

`npm run verify:wasm-bridge-sync` fails if the generated trees drift from TypeScript emit.

## Toolchain pin

| What | Value | Where |
|------|-------|-------|
| emsdk / emcc | **6.0.9** | `src/contracts/wasm_compile_flags.json` → `emsdkVersion` |
| std / opt / port / `-s` flags | one list | same JSON (`std`, `opt`, `usePort`, `sFlags`, `jsOutputName`) |
| Exports | — | `src/contracts/wasm_exports.json` |

- CI `setup-emsdk` `version:` must equal `emsdkVersion` (`npm run verify:wasm-invariants` fails otherwise). Never `latest`.
- `build.sh` runs `scripts/emcc-version-gate.sh` before `em++` and refuses a mismatched emcc. The minified glue does **not** embed the emcc version, so the gate is on the toolchain, not the artifact.
- `build.sh` reads the flag JSON and may not hardcode `-s` flags or `--use-port` (enforced by `verify:wasm-invariants`). It is the only build; `CMakeLists.txt` was removed.
- Cloud VMs / Jules: plain `npm run build` uses the committed artifacts. Never commit artifacts from a non-pinned emcc (e.g. 3.1.x). `ALLOW_EMCC_VERSION_MISMATCH=1` exists for local experiments only.
- Bumping the pin: change `emsdkVersion` and `.github/workflows/wasm.yml` together, rebuild, commit artifacts in the same PR.

## Build commands

```bash
npm run wasm:build      # Requires emsdk; fails if emcc missing. Also writes pixelocity_wasm.d.ts
npm run wasm:build:debug  # ASSERTIONS=2 + DWARF → pixelocity_wasm.debug.* (gitignored; ?wasm_debug=1)
npm run wasm:contracts  # Regenerate bridge wrappers + generated/contracts.h (no emcc)
npm run wasm:validate   # Checks sizes, magic, exports, generated-copy equality
npm run verify:wasm-bridge-sync  # TypeScript SoT vs generated JS
npm run wasm:clean      # Remove build/ and public/wasm/
```

### Skipping WASM build intentionally
`npm run build` never compiles unless `WASM_BUILD=1`: its `prebuild` runs
`build.sh --if-requested`, which regenerates the contracts and bridge copies and then uses
the committed artifacts. `SKIP_WASM_BUILD=1 npm run wasm:build` likewise only syncs.

### C++ IDE index (clangd)

`build.sh` is the only build. For clangd, generate a compile database from the same
contract (`src/contracts/wasm_compile_flags.json`: flags and the `sources` TU list):

```bash
source <emsdk>/emsdk_env.sh   # em++ on PATH, the pinned version
npm run wasm:build            # once: fetches the emdawnwebgpu headers into EM_CACHE
npm run wasm:compdb           # writes wasm_renderer/compile_commands.json (gitignored)
$EMSDK/upstream/bin/clangd --check=wasm_renderer/device.cpp
```

Each entry is `em++ --cflags` (wasm32 target, EM_CACHE sysroot) plus build.sh's exact
flag list, `-I` for `wasm_renderer/` and the port headers. `wasm_renderer/.clangd`
removes the em++-only `-s…` / `--use-port=…` settings. Use emsdk's own clangd so its
clang matches em++. `verify:wasm-invariants` keeps the database, `.clangd` and build.sh
on the one flag list and TU list. Do not reintroduce CMake: its two-step emdawn compile
leaked `-sUSE_WEBGPU=1`.

## CI pipeline

1. **`wasm` job** (`wasm.yml`) — installs emsdk (`mymindstorm/setup-emsdk@v14`), restores EM_CACHE, builds release (ASYNCIFY_ADVISE gate) and debug profiles, `wasm:validate`, blocking byte-equality with the committed `.wasm`/`.js`/`.d.ts`, `verify:wasm-bridge-sync`, WASM Jest suites, uploads artifacts.
2. **`test` job** (`ci.yml`) — unit tests + CRA build against the committed artifacts, re-validates them (`verify:toolchain-foundation` includes bridge sync).
3. **`test-wasm-e2e` job** (`wasm.yml`) — downloads artifacts, production build, Playwright smoke on SwiftShader for the release and the debug profile.

See [`WASM_BUILD_CI_GUIDE.md`](../docs/WASM_BUILD_CI_GUIDE.md) for troubleshooting.
